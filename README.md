# Neon Runner

Vertical arcade shooter. Your ship **auto-fires continuously** (no
button — just aim by moving), dodge/blast waves of enemies, boss
every 5th wave, power-ups drop from kills.

This zip contains a **ready-to-open Xcode project** — no manual
project setup needed this time.

```
NeonRunner.xcodeproj/     ← open this in Xcode
NeonRunner/
  NeonRunnerApp.swift
  ContentView.swift        (WKWebView wrapper, loads www/)
  Info.plist
  Assets.xcassets/
    AppIcon.appiconset/    (1024x1024 icon, Xcode generates the rest)
  www/                     ← the actual game (html/css/js)
www_preview/                ← identical copy of www/, for testing
                             in a plain browser without Xcode
```

## What changed from the last version
- **Auto-fire, unlimited** — the ship fires continuously on its own;
  Rapid Fire power-up still speeds it up further. No fire button.
- **Joystick moved to bottom-center** (was bottom-left) — it's the
  only touch control now.
- **App icon** added (neon ship on starfield), wired into the asset
  catalog — Xcode auto-generates every required size from the one
  1024×1024 source.
- **Full Xcode project this time**, not just source files to paste
  in — `NeonRunner.xcodeproj` is ready to open directly.

## Step 1 — sanity check in a browser (optional but fast)
Open `www_preview/index.html` in a desktop browser, or drag the
`www_preview` folder onto a local server, to confirm the gameplay
feels right before touching Xcode. Arrow keys/WASD to move — you'll
see it auto-firing immediately.

## Step 2 — open and run
1. On a Mac, double-click `NeonRunner.xcodeproj` to open it in Xcode
   (15+ recommended).
2. Select a Simulator (or your device) from the scheme bar.
3. Press **Run**. It should launch full-screen in landscape with the
   ship auto-firing and the joystick at the bottom-center.

## Step 3 — build the IPA
1. Select **your physical device** (not a Simulator) as the run
   target — Simulators can't produce an installable IPA.
2. In the project settings → **Signing & Capabilities**, choose your
   Apple ID as the team (a free account works for personal/dev
   signing) and adjust `PRODUCT_BUNDLE_IDENTIFIER` if `com.example.neonrunner`
   collides with something already on your account — any unique
   reverse-DNS string works, e.g. `com.yourname.neonrunner`.
3. **Product → Archive**.
4. When the Organizer window opens: **Distribute App → Development**
   (or **Ad Hoc**) → follow the prompts → **Export**. You'll get a
   folder containing the `.ipa`.
5. Sideload that `.ipa` via SideStore as usual.

## Honesty note on this project file
I hand-built `project.pbxproj` (Xcode's project format) directly
rather than exporting it from Xcode itself, since I don't have Xcode
or macOS available to generate/verify it here. I checked it
carefully — structurally balanced, every internal reference resolved
— but I can't guarantee it opens with zero issues on the first try
the way a project generated by Xcode's own wizard would.

If Xcode shows any project-corruption error on open, the reliable
fallback is: File → New → Project → iOS App (SwiftUI) in Xcode, then
drag in `NeonRunnerApp.swift`, `ContentView.swift`, the `www` folder
(as a **folder reference** — blue icon, this part matters), and the
`Assets.xcassets` folder, replacing the template's own copies. Tell
me what error Xcode shows and I'll help fix it either way.

## Extending it
- New enemy type: add to `ENEMY_TYPES` in `game.js` + a movement
  branch in `Enemy.update()`.
- New power-up: add a case in `applyPowerUp()` + color/glyph in
  `PowerUp.draw()`.
- Icon: regenerate `Assets.xcassets/AppIcon.appiconset/icon-1024.png`
  (must stay exactly 1024×1024, no transparency, no rounded corners
  — iOS masks the shape itself).
